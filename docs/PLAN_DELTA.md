# 기획안 → 구현 변경 이력

PDF 3건(기획안 / 해외 사례 / 개발 방향 제언)을 구현으로 옮기면서 **무엇을 그대로 두고,
무엇을 바꿨으며, 왜 바꿨는지** 기록한 문서입니다. 기획안 개정(제언 §12-5) 시 이 문서를
근거로 쓰십시오.

---

## 1. 그대로 유지한 것

기획의 "무엇을·왜"는 손대지 않았습니다.

| 항목 | 상태 |
|---|---|
| 문제 정의 (경고등의 의미·긴급도를 모른다) | 유지 |
| 4단계 권고 체계 (즉시 정차 / 즉시 정비 / 목적지 후 / 여유) | 유지 |
| `긴급도 = 기본 심각도(1~3) + Σ환경 가중치(0~3)` | 유지 |
| 기본 심각도 3 = 환경 무관 최소 3등급 | 유지 |
| 시나리오 A·B·C | 유지 (단위 테스트로 검증) |
| 등급은 규칙, LLM 은 설명만 | 유지 — 더 강하게 적용 |
| 화면 5종 (홈 / 상세 / 권고 / 자가진단 / 이력) | 유지 |
| 정상 회색 / 주의 노랑 / 위험 빨강 | 유지 |

## 3. SDK 실측으로 제언 문서와 달라진 것 ⭐

AAR 을 디컴파일해 실제 API 를 확인한 결과입니다 (`SDK_API_NOTES.md`).

### 3-1. 냉각수 과열 — 대체 불필요 (제언 §6 수정)

제언 문서: *"냉각수 과열은 SDK 19개 도메인에 대응 항목이 보이지 않음 → EV battery 로 대체 권장"*

**실제**: `TelltaleType.ENGINE_TEMPERATURE` 로 직접 읽을 수 있습니다.
기획안의 "냉각수 과열 → 기본 심각도 3" 항목이 **원안 그대로 살아있습니다.**

### 3-2. 차속 API 부재 — 새 제약 (제언에 없던 항목)

제언 문서: *"도로 종류는 지도 API 또는 차량 속도로 판단", "차속·ADAS 로 가중치 산출"*

**실제**: Vehicle SDK 21개 도메인에 **차량 속도 API 가 없습니다.** 크루즈 *목표* 속도만 존재합니다.

**대응**: `Odometer.getCurrentDistanceDriven()` 델타로 속도를 추정합니다.
실차 전환 시 `android.car` 의 `PERF_VEHICLE_SPEED` 로 교체해야 정확합니다.

### 3-3. 도메인 21개 (제언 표기 19개)

`Gear`, `Brake` 가 별도 도메인으로 존재합니다.

### 3-4. 권한 네임스페이스

제언: `CAR_* / CONTROL_CAR_*` → **실제**: `pleos.car.permission.*`
protectionLevel 이 normal 이라 런타임 권한 대화 상자가 없다는 결론은 동일합니다.

### 3-5. 검증 과제 1·4 통과 → 대표 시나리오 유지

제언 §7 은 "과제 1(Light 명령 vs 실제)이 실패하면 대표 시나리오를 타이어 공기압으로 교체해야
한다"고 경고했습니다. **두 과제 모두 통과**해 시나리오 A·B(전조등)를 그대로 씁니다.

## 4. 범위를 조정한 것 (판단과 근거)

| 항목 | 조정 | 이유 |
|---|---|---|
| **3D 차량 모델** | 2D 탑다운 도해로 구현 | 부위별 메시가 분리된 glTF 에셋이 없음. 에셋 없이 3D 뷰어를 붙이면 빈 화면이 됨. 교체 지점을 `ui/car/CarDiagram.kt` 한 파일로 격리 |
| **정비소 연결 (아이디어 B)** | 리포트 생성까지 | 지도·예약 API 는 키와 제휴 필요. 정비소에 전달 가능한 요약을 화면에 만들어 두는 편이 시연에 더 유효 |
| **예측 정비 (아이디어 C)** | 주행거리 기반 소모품 주기만 | 제언 §8 의 "C 는 범위를 좁히라" 권고를 따름. 시연 시간 안에 의미 있는 추이를 모을 수 없음 |
| **단계적 알림 (아이디어 A)** | 등급별 시각 강조까지 | 4등급 깜빡임·색 강조는 구현. 음성·문자·긴급출동 연결은 미구현 |
| **외관 손상 스캔 (E)** | 미구현 | IVI 에 적합한 카메라 접근 수단 없음. 제언 §8 "제외" 판정 |
| **운전자 상태 결합 (F)** | 미구현 | SDK 에 운전자 모니터링 없음. 제언 §8 "제외" 판정 |
| **업무용 운전자 모드 (D)** | 미구현 | 제언 §8 "발표용" 판정 |

## 5. 기획안에 없던 추가 구현

| 항목 | 이유 |
|---|---|
| **시연 환경 오버라이드** | 심사장에서 밤↔낮, 맑음↔비를 즉석 전환. 제언 §3-1 의 핵심 데모를 실행 가능하게 만듦. **"시연 모드" 배지로 실측/시연값 구분** |
| **오프라인 일출·일몰 계산** | 낮/밤은 시나리오 A·B 의 분기 조건. API 의존은 시연 리스크 |
| **정보성 표시등 제외 목록** | 방향지시등을 고장으로 보고하면 깜빡이 켤 때마다 오탐 |
| **단위 테스트 (시나리오 A·B·C)** | 가중치 표를 고치면 테스트가 먼저 깨짐 — 규칙 변경이 조용히 시연을 망가뜨리는 것을 방지 |
| **미지원 속성 null 흡수** | 에뮬 ≠ 실차 리스크(제언 §11)에 대한 코드 레벨 대응 |
