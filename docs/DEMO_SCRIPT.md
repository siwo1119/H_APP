# 시연 대본 — Virtual Console 조작 순서

심사장에서 **녹화 영상 없이 즉석 재현**하기 위한 대본입니다.
제언 문서 §3-1 의 "시연 대본을 Virtual Console 조작 순서로 작성하라"에 대한 산출물입니다.

---

## 0. 사전 준비 (발표 10분 전)

```powershell
# 1. 에뮬레이터 기동 (콜드 부팅 2~4분, 2회차부터 ~40초)
cd $env:USERPROFILE
.\launch_avd.ps1

# 2. 앱 설치
cd C:\Users\siwoo\H_APP
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-17.0.21.9-hotspot'
.\gradlew.bat installDebug

# 3. 앱 실행
adb shell am start -n com.cardoctor.advisor/.MainActivity

# 4. Virtual Console 열기 (별도 모니터 권장)
adb forward tcp:8088 tcp:8088
start http://127.0.0.1:8088/
```

> ⚠️ **Virtual Console 은 브라우저로 한 번 열어야 쓰기가 활성화됩니다.**
> 열기 전에는 모든 쓰기가 `{"error":"emulator_inactive"}` (503) 으로 거부됩니다.
> 발표 전에 반드시 열어 두세요.

### 이 에뮬레이터 이미지에서 동작하는 항목

실기기 확인 결과(`docs/SDK_API_NOTES.md` §9), **타이어 공기압·엔진오일·브레이크액·안개등은
이 이미지에서 미지원**입니다. 시연은 **경고등(Telltale)** 중심으로 구성하십시오.

| 쓸 수 있는 것 | 쓸 수 없는 것 |
|---|---|
| 경고등 37종, 등화(로우빔·하이빔·미등), 와이퍼, 기어, 도어, 주행거리, EV 충전량 | 타이어 공기압, 엔진오일·브레이크액·변속기오일, 워셔액, 안개등, 안전벨트 경고 |

**체크리스트**
- [ ] 에뮬레이터 화면이 2560×1440 으로 뜨고 UI 가 겹치지 않는가
- [ ] 앱 홈 화면에 차량 도해가 보이는가
- [ ] Virtual Console 이 200 으로 열리는가
- [ ] 앱 하단 탭 4개(홈/자가진단/정비 권고/이력)가 동작하는가
- [ ] **네트워크를 꺼도** 진단·등급이 나오는지 한 번 확인 (폴백 검증)

## 1. 도입 — 문제 제기 (30초)

> "경고등이 켜졌을 때, 지금 차를 세워야 하는지 아닌지 아시겠습니까?
> 같은 고장이라도 낮이냐 밤이냐에 따라 답이 다릅니다.
> 저희 앱은 '고장이 있다'가 아니라 **'지금 무엇을 하라'**를 답합니다."

화면: 앱 홈 (이상 없음 상태)

---

## 2. 시나리오 A — 낮, 전조등 이상 → 2단계 (1분)

> **실측 확인됨.** 기획안 원안은 "로우빔 미점등(명령≠실제)"이었으나, 이 에뮬레이터 이미지는
> 로우빔의 명령과 실제를 따로 바꿀 수 없습니다(콘솔이 둘을 항상 일치시킴).
> 같은 **등화 계통**이면서 콘솔로 자유롭게 켤 수 있는 **AFS(적응형 전조등)** 경고등을 씁니다.
> 등급 변화 서사는 원안과 동일합니다.

| | 조작 | 기대 결과 |
|---|---|---|
| A-1 | Virtual Console → **Safety → Telltales → AFS** → `On` | 앱: 좌측 전조등 **노란색**, "적응형 전조등 이상" 추가 |
| A-2 | 앱 홈에서 **[낮]** 토글 | **2단계 · 목적지 후 정비** / 긴급도 **2점** |

> 멘트: "앱이 고장코드를 읽은 게 아닙니다. Vehicle SDK 에는 고장코드 API 자체가 없습니다.
> 상태 신호에서 **추론**한 겁니다."

---

## 3. 시나리오 B — 밤, **같은 고장** → 3단계 ⭐ 핵심 장면 (1분)

| | 조작 | 기대 결과 |
|---|---|---|
| B-1 | 앱 홈 → 시연 전환 → **[밤]** 클릭 | 전조등이 **빨간색으로 깜빡임**, **3단계 · 즉시 정비** 로 승격 (**5점**) |
| B-2 | 진단 목록에서 해당 항목 클릭 | 상세 화면 진입 |
| B-3 | **"이 등급이 나온 근거"** 카드를 가리킴 | `기본 심각도 +2` / `야간 운행 — 시야 확보 필요 +3` / `합계 5점` |

> 멘트: "**차는 아무것도 안 바뀌었습니다. 바뀐 건 시간대뿐입니다.**
> 그런데 판단이 2단계에서 3단계로 올라갔습니다.
> 그리고 왜 올라갔는지가 점수로 화면에 그대로 나옵니다 — 블랙박스가 아닙니다."

**이 장면이 전체 발표에서 가장 강한 데모입니다. 천천히 하세요.**
`[낮]` ↔ `[밤]` 을 두 번쯤 왕복하며 배지 색과 점수가 같이 바뀌는 걸 보여주세요.

## 4. 안전 핵심 부품 — 하한 규칙 (1분)

| | 조작 | 기대 결과 |
|---|---|---|
| C-1 | 앱에서 **[실측값으로]** 눌러 초기화 | 환경이 실제 값으로 돌아감 |
| C-2 | Telltales → **EngineTemperature** → `On` | "냉각 계통 과열", **3단계 · 즉시 정비** (3점) |
| C-3 | 앱에서 **[낮] + [맑음]** 으로 가장 온화한 환경 설정 | **그래도 3단계 아래로 내려가지 않음** |
| C-4 | 상세 화면 근거 확인 | "안전 핵심 부품이라 환경과 무관하게 최소 3단계로 판정됐습니다" |

> 멘트: "점수만 보면 3점이라 2단계입니다. 그런데 냉각 계통은 안전과 직결돼서
> **환경이 아무리 좋아도 3단계 밑으로 안 내려가게** 규칙에 하한을 박아 뒀습니다."

## 돌발 상황 대응

| 증상 | 대응 |
|---|---|
| 앱이 "Vehicle Service 에 연결하지 못했습니다" | `adb shell dumpsys package ai.pleos.playground.service.vehicle` 로 서비스 확인 → 앱 재시작 |
| Virtual Console 이 안 열림 | `adb forward --remove-all` 후 `adb forward tcp:8088 tcp:8088` 재실행 |
| 값을 바꿨는데 앱에 반영이 늦음 | 폴링 주기 4초. 즉시 보려면 홈에서 **[전체 점검]** |
| AI 설명이 "생성하는 중"에서 멈춤 | 15초 타임아웃 후 자동으로 오프라인 문구로 바뀜 — 그대로 두면 됨 |
| 네트워크 사고 | 영향 없음. 날씨만 UNKNOWN 이 되고 나머지는 동작 — **오히려 시연 포인트로 활용** |
| 에뮬레이터가 느림 | 콜드 부팅 필수(VHAL). quick boot 으로 바꾸지 말 것 |

## 시연에서 하지 말아야 할 것

- **[실측값으로] 를 누르지 않고 시나리오를 넘어가지 말 것** — 이전 오버라이드가 남아 혼선
- 환경 토글을 너무 빨리 연타하지 말 것 — 등급 재계산이 따라오는 걸 보여주는 게 포인트
- "AI 가 진단했다"고 말하지 말 것 — **등급은 규칙, LLM 은 설명만**이 핵심 메시지

## 부록 — 검증된 조작 명령 (복붙용)

아래는 실제로 실행해 **앱이 반응하는 것을 확인한** 명령입니다.
Virtual Console UI 대신 터미널로 시연하거나, 리허설 자동화에 쓰십시오.

```bash
VC=http://127.0.0.1:8088

# ── 시나리오 A/B : 등화 계통 이상 (낮 2단계 ↔ 밤 3단계) ──────────────
curl -X PUT "$VC/vehicle/telltales/simulator?type=AFS&state=On&color=Yellow"
#   → 앱: "적응형 전조등 이상", 좌측 전조등 하이라이트
#     밤  = 기본 2 + 야간 3 = 5점 → 3단계 즉시 정비 (빨강)
#     낮  = 2점             → 2단계 목적지 후 정비 (노랑)
#   앱 홈의 [낮] / [밤] 토글로 즉석 전환

# ── 안전 핵심 부품 : 하한 규칙 ────────────────────────────────────
curl -X PUT "$VC/vehicle/telltales/simulator?type=EngineTemperature&state=On&color=Red"
#   → "냉각 계통 과열" 3점 → 환경과 무관하게 3단계

curl -X PUT "$VC/vehicle/telltales/simulator?type=ABS&state=On&color=Red"
#   → "ABS 제동 보조 이상" 2점 → 2단계

# ── 깜빡임 승격 ───────────────────────────────────────────────────
curl -X PUT "$VC/vehicle/telltales/simulator?type=ABS&state=Blink&color=Red"
#   → 상시 점등보다 한 단계 높게 판정됨

# ── 정보성 표시등은 고장으로 잡히지 않음 (오탐 방지 시연) ──────────
curl -X PUT "$VC/vehicle/telltales/simulator?type=TurnSignalLeft&state=Blink&color=Green"
#   → 앱: 변화 없음. 방향지시등은 고장이 아니다

# ── 해제 ──────────────────────────────────────────────────────────
curl -X PUT "$VC/vehicle/telltales/simulator?type=AFS&state=Off&color=Yellow"

# ── 현재 상태 확인 ────────────────────────────────────────────────
curl -s "$VC/vehicle/state" | grep -o '"actual":{[^}]*}'
```

**파라미터 주의**: 경고등은 `area` 가 아니라 **`type`** 이고 **`color` 가 필수**입니다.
다른 기능의 파라미터 이름은 `curl -s "$VC/vehicle/catalog"` 의
`control.field` / `control.area_field` / `control.params` 를 보면 됩니다.

### 앱 조작을 adb 로 (리허설 자동화)

```bash
adb shell am force-stop com.cardoctor.advisor
adb shell am start -n com.cardoctor.advisor/.MainActivity

# 홈 화면 시연 토글 좌표 (2560x1440 기준)
adb shell input tap 1674 508    # [낮]
adb shell input tap 1730 508    # [밤]
adb shell input tap 1792 508    # [맑음]
adb shell input tap 1854 508    # [비]
adb shell input tap 1930 508    # [고속도로]
adb shell input tap 2043 508    # [실측값으로]

# 화면 캡처
adb shell screencap -p /sdcard/s.png && adb pull /sdcard/s.png .
```

> 좌표는 Pleos 홈 화면이 앱을 멀티윈도우로 띄우는 위치에 따라 달라질 수 있습니다.
> 어긋나면 캡처해서 다시 재어 쓰십시오.
